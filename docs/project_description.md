1.  Предметная область
Проект «Focus+Notes» относится к сфере персональной продуктивности и управления вниманием. Его центральная идея — помочь пользователю сосредоточиться на работе или учёбе, исключив отвлекающие факторы и предоставив удобное пространство для быстрых заметок.
Расширение работает прямо в браузере, что делает его особенно удобным: пользователь не устанавливает отдельное приложение, а получает инструмент там, где он проводит большую часть времени. Продукт решает сразу несколько задач. Во-первых, позволяет блокировать сайты, которые мешают сосредоточиться — например, социальные сети или видео-платформы. Во-вторых, реализует «режим фокусировки», где можно задавать таймеры, например, по методике Pomodoro, и работать циклами. И, наконец, оно позволяет сохранять идеи и небольшие заметки в момент работы. Заметки не остаются только на одном устройстве: они синхронизируются через серверную часть и доступны пользователю в любом браузере, где установлено расширение.
Таким образом, предметная область проекта — это браузерные расширения для продуктивности, сочетающие функциональность блокировщика и заметочника с облачной синхронизацией.
 
2.  Архитектура
Архитектура проекта строится по принципу клиент–серверной модели с элементами микросервисного подхода. На стороне клиента располагается само расширение браузера, которое представляет собой комбинацию пользовательского интерфейса (графические окна, всплывающие панели) и логики блокировки сайтов. Оно отвечает за взаимодействие с пользователем, отображение списка заметок, настройку параметров фокусировки и выполнение правил блокировки в браузере.
Серверная часть реализована на Python и использует фреймворк FastAPI. Она предоставляет REST API для синхронизации данных между устройствами. В серверной части выделяется несколько ключевых модулей. Первый отвечает за аутентификацию и авторизацию пользователей. Он может быть выделен в отдельный сервис, чтобы упростить масштабирование и использование разных схем безопасности (например, OAuth2). Второй модуль — основной API для работы с заметками и списками блокировок. Он обрабатывает запросы от расширения, хранит данные в базе и возвращает актуальные состояния.
Данные сохраняются в реляционной базе PostgreSQL. Это надёжное решение, которое позволяет хранить структурированную информацию о пользователях, их заметках и индивидуальных настройках. Для ускорения работы и хранения временных данных может использоваться Redis — он пригодится для кеширования активных сессий или временных токенов.
Общая архитектура рассчитана на то, чтобы начинать в простом виде — клиентское расширение и монолитный сервер, развернутый в контейнере. Но при росте нагрузки систему можно безболезненно развивать: выделить авторизацию в отдельный сервис, подключить очередь заданий для фоновых задач (например, резервное копирование или отправку уведомлений), а также масштабировать API горизонтально. 

  3.  Части проекта
Проект можно разделить на три основных компонента.
Первый компонент — это фронтенд, реализованный в виде браузерного расширения. Он предоставляет пользователю графический интерфейс: всплывающее окно для добавления заметок, панель управления списком заблокированных сайтов и экран для настройки режимов фокусировки. Визуальная часть может быть построена с использованием React, чтобы упростить работу с состояниями и компонентами.
Второй компонент — это серверное приложение. Оно реализует всю бизнес-логику: хранит данные о пользователях и их заметках, проверяет авторизацию, обеспечивает синхронизацию и применяет правила безопасности. Сервер отвечает на запросы расширения, обрабатывает CRUD-операции и возвращает структурированные ответы в формате JSON.
Третий компонент — база данных. Здесь содержатся таблицы пользователей, их заметок и списков блокировок. Именно база обеспечивает консистентность и возможность быстрого доступа к данным.
Эти части соединяются между собой с помощью HTTP-запросов, а для контейнеризации и развёртывания всего окружения используется Docker.
 
4.  Pipeline
Работа над проектом организуется через современный CI/CD-pipeline. Разработчик начинает с локальной работы: создаёт новую ветку, например feat/uni, и фиксирует изменения в Git. После пуша ветки на GitHub открывается pull request в основную ветку разработки dev.
При создании pull request автоматически запускаются проверки. Сначала выполняются модульные и интеграционные тесты, написанные на Pytest для бэкенда и Jest для фронтенда. Результаты тестов дополняются метриками покрытия кода, которые снимает библиотека coverage.py. Затем запускается статический анализ кода. В Python-части это flake8 для стиля, mypy для проверки типов и bandit для анализа безопасности. Если всё проходит успешно, pull request уходит на ревью.
После того как изменения проверены и одобрены, они вливаются в ветку dev. Периодически содержимое dev объединяется с основной веткой main, что инициирует процесс сборки Docker-образов и автоматический деплой на сервер или в staging-среду. Таким образом, весь цикл от написания кода до развертывания строго контролируется, а ошибки выявляются ещё на ранних этапах.
 
5.  Технологии и их преимущества
Основой серверной части является Python. Этот язык выбран благодаря широкой экосистеме, богатому выбору библиотек и простоте написания чистого кода. В качестве фреймворка используется FastAPI, который отличается высокой производительностью и встроенной поддержкой асинхронных операций, а также удобной генерацией документации Swagger.
В качестве базы данных применяется PostgreSQL. Это зрелое, надёжное решение, которое поддерживает сложные запросы, транзакции и расширения. Для временных данных используется Redis, который обеспечивает очень быстрый доступ в памяти и идеально подходит для кешей и хранения токенов.
Фронтенд реализован на JavaScript с использованием React. Такой выбор позволяет строить модульный интерфейс, легко управлять состояниями и использовать современную экосистему компонентов. Браузерное API обеспечивает доступ к функциям блокировки сайтов и управлению вкладками.
Контроль версий ведётся в Git, а GitHub используется как платформа для командной работы и CI/CD. GitHub Actions дают возможность настроить полный процесс сборки, тестирования и анализа кода без необходимости в дополнительных сервисах.
Важным элементом является Docker, который позволяет упаковать серверную часть и базу данных в контейнеры. Это гарантирует одинаковую среду разработки, тестирования и продакшна, упрощает деплой и масштабирование.
В совокупности все эти технологии создают устойчивую и удобную инфраструктуру для разработки и эксплуатации проекта. Они обеспечивают баланс между скоростью разработки, удобством работы команды и возможностью масштабирования системы в будущем.
